# 改良計画（fork: 日本語対応 + 送信元ドメイン照合）

目標: PC でも、スマホの SMS 認証コード自動入力のように、メールで届いた認証コードを 1 タップで入力できるようにする。

## 必須要件

1. **日本語メールへの対応**
2. **送信元ドメインと入力先サイトのドメインの照合**（不一致なら自動入力しない）

## 脅威モデル（何から守るか）

| 脅威 | 対策 |
| --- | --- |
| フィッシングサイト `bank-login.example` に、本物の `bank.co.jp` から届いたコードを入力させる | 送信元の登録可能ドメイン（eTLD+1）と、入力先フレームの登録可能ドメインが一致しない限り入力しない |
| `From: no-reply@bank.co.jp` を偽装したメール | Gmail 自身が付けた（最上段の、`mx.google.com` の）`Authentication-Results` で `dmarc=pass`、または From と整合する `dkim=pass` / `spf=pass` を確認できた送信元だけを信頼する |
| 攻撃者がメール本文に偽の `Authentication-Results` を仕込む | 最上段のヘッダーだけを見て、authserv-id が Google のものでなければ未検証として扱う（fail closed） |
| 表示名の偽装 `"x@bank.co.jp" <a@evil.com>` | 山括弧内の addr-spec だけを使う。複数アドレスは拒否 |
| `evil.co.jp` と `bank.co.jp` を同じドメインとみなす誤り | Public Suffix List を同梱して eTLD+1 を計算する |
| 検索中にタブが別サイトへ遷移する、別オリジンの iframe に入力してしまう | 入力する瞬間、入力するフレーム内で、そのフレームのオリジンを再確認する |
| 迷惑メールフォルダのコード | 自動入力の対象外（確認付きの手動入力のみ） |
| ページのスクリプトによるコードの盗み見 | 自動提案モードでは、ユーザーが実際にクリック（`isTrusted`）するまで、コードを Service Worker の外に出さない |
| ページからのトリガーで勝手にサインイン画面が開く | ページ起点の処理では非対話の認証だけを使う |

## 設計

### 1. ドメイン照合（`core/domain.js`、`core/sender.js`）
- 同梱 PSL（`scripts/update-psl.mjs` で生成）による eTLD+1 判定。IP・localhost・空ホストは一致扱いにしない。
- `From` の厳密パース、`Authentication-Results` の検証（DMARC、または DKIM/SPF の relaxed alignment）。
- 照合結果は `match`（一致）・`trusted`（ユーザーが許可した組み合わせ）・`mismatch`（不一致）・`unverified`（送信元を認証できない）・`spam` のいずれか。
- 組み合わせの許可は「認証済みの送信元ドメイン × サイトのドメイン」の単位で、ユーザーが明示的に確認したときだけ保存する。組み込みの別名表は持たない（推測による信頼を避ける）。

### 2. 検索ロジック（`core/finder.js`）
- 各メールに送信元ドメインと照合結果を付ける。
- 入力先と一致する最新メールを選ぶ。不一致のコードがあっても、それを入力したり、一致するコードを妨げたりしない。

### 3. 入力（`background/fill.js`、`content/autofill.js`）
- 各フレームの probe が自分の `origin` を返す。一致するフレームだけを候補にする。
- `fill` の中でも期待する登録可能ドメインをもう一度確認する（遷移対策）。
- HTTPS 以外のページには入力しない。
- ページ上のトーストにはコードを出さない（成功時を除く）。送信元は検証済みドメインで表示する。

### 4. 日本語メール（`core/extract.js`）
- NFKC 正規化（全角数字・全角コロンなど）。
- ラテン文字と CJK を区別した境界判定（`認証コードは123456です` を読めるようにする）。
- 日本語のラベル（認証コード、確認コード、認証番号、ワンタイムパスワード、パスコードなど）と、`「」【】` などの括弧。
- 日本語の否定語（クーポンコード、招待コード、QRコード、〒、円、注文番号、会員番号、電話番号など）。
- 文字コード: ISO-2022-JP、Shift_JIS（`cp932` などの別名を含む）、EUC-JP のテスト。
- フィクスチャ: 陽性と陰性をそれぞれ十分な数だけ用意する。

### 5. 入力欄の検出（`content/autofill.js`）
- 日本語ラベルの部分一致（「認証コード」「確認コード」「ワンタイム」など）。
- 日本語の否定語（「セキュリティコード」はカードの CVV にも使われるため、カード周辺では除外）。

### 6. 1 タップの体験
- **基本（追加権限なし）**: ポップアップを開くと自動で検索を始める（1 クリック）。ショートカット `Alt+Shift+F` は従来どおり。
- **自動提案（オプトイン、`optional_host_permissions`）**: 認証コード欄にフォーカスすると、欄の下に「example.com からのコード ••••56 ― クリックで入力」というチップを表示する。クリックした時点で、Service Worker が照合を再確認してから入力する。

### 7. UI と文書
- `_locales/ja` を追加。
- 不一致・未検証のときの警告表示と、「この組み合わせを信頼して入力」の確認導線を追加。
- README / PRIVACY / how-it-works を更新。
